# EMQX Kubernetes Deployment

English | [简体中文](README.zh-CN.md)

`cluster.yaml` is the production EMQX long-connection cluster manifest: 3 persistent Core nodes hold cluster state, and 2 stateless Replicant nodes accept device connections. Clients should connect to `emqx-listeners.emqx.svc.cluster.local:1883`; the Operator points that Service at the Replicant nodes.

The default community license of EMQX 5.9 and later supports only a single node. This manifest reads the cluster license from the `emqx-license` Secret on all nodes; do not apply the cluster manifest before creating that Secret.

Install the pinned Operator version, create the license Secret, then deploy the cluster:

```bash
curl -fsSL https://github.com/emqx/emqx-operator/releases/download/2.3.0/install.yaml | kubectl apply --server-side=true -f -
kubectl -n emqx create secret generic emqx-license --from-literal=key="$EMQX_LICENSE_KEY"
kubectl apply -f deploy/emqx/cluster.yaml
kubectl wait --for=condition=Ready emqx/emqx -n emqx --timeout=10m
```

In production, point `emqx-listeners` at an internal or public L4 LoadBalancer, and mount a certificate Secret for the MQTT TLS listener before exposing it publicly. Keep the Dashboard on the private network — expose it through a controlled entrypoint or a temporary `kubectl port-forward`; never open it directly to the public internet.

## Local Mode

Local uses the same Operator, namespace, Service DNS, PVCs, and listener Service, but applies the single-Core-node manifest [`cluster.local.yaml`](cluster.local.yaml). The default community license only permits this mode, so it is used solely to verify connections, shared subscriptions, reconnects, and publish flows — it provides no production HA.

The auth-callback token is injected via an EMQX environment-variable override: EMQX 6 does not expand `${VAR}` placeholders in the authn HTTP template, and per-key overrides like `EMQX_AUTHENTICATION__1__HEADERS__x_iot_auth_token` are rejected as `unknown_env_vars`. The only viable injection path is overriding the entire headers map with `EMQX_AUTHENTICATION__1__HEADERS` (a JSON value). That value is stored in the `EMQX_AUTHN_HEADERS_JSON` key of `iot-runtime-secrets` in the emqx namespace, generated by the deploy script:

```bash
scripts/helm-deploy-local.sh   # creates iot-runtime-secrets (with EMQX_AUTHN_HEADERS_JSON) in the emqx namespace
kubectl apply -f deploy/emqx/cluster.local.yaml
kubectl wait --for=condition=Ready emqx/emqx -n emqx --timeout=10m
```

The production manifest `cluster.yaml` uses the same mechanism: when creating `iot-runtime-secrets`, it must include `EMQX_AUTHN_HEADERS_JSON` (full JSON content, e.g. `{"content-type":"application/json","x_iot_auth_token":"<token>"}`).

Note: the local single-node license crashes during rolling updates due to the transient double-core state (`SINGLE_NODE_LICENSE`). After updating the EMQX CR, run `kubectl delete sts -n emqx --all` to let the Operator rebuild the single node.

Local Compose does not run an EMQX container; instead it port-forwards `emqx-listeners:1883` and `emqx-dashboard:18083` to the host, so both the demo inside Docker and host-side MQTT clients go through the same Kubernetes EMQX Service.
